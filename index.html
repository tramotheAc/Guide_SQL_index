Le principe en une phrase

Un index, c'est l'index d'un livre

Une structure qui permet au moteur de localiser les données sans parcourir toute la table. Il accélère les lectures, mais il a un coût : chaque écriture (INSERT / UPDATE / DELETE) doit aussi le mettre à jour. Tout l'art consiste à trouver le bon équilibre.

Méthode

Une stratégie d'indexation en 4 temps

1

Poser la base

Un index clustered sur la clé primaire de chaque table pour asseoir les performances globales.

2

Requêtes fréquentes

Des index non-clustered sur les colonnes qui reviennent dans les WHERE et les JOIN.

3

Cas particuliers

Filtered pour les sous-ensembles, columnstore pour l'analytique intensive.

4

Réglage fin

Colonnes incluses pour éviter les lookups, index calculés pour les formules récurrentes.

Trop d'index nuit

Chaque index ralentit les écritures et occupe de l'espace. Indexez selon vos patterns de requêtes réels, pas « au cas où ». Un index jamais lu mais toujours mis à jour est une dette pure — à surveiller et à supprimer.
